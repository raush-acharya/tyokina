# TyoKina case study: handoff

Read this first if you are picking up the case study (or the product images) in a new chat. For the app itself, read `../HANDOFF.md`.

## What exists

1. **A presentation site** (`case-study/`): 39 slides, presented one section at a time, built with Vite and GSAP (SplitText headlines, interruptible transitions). It tells the process behind TyoKina: Empathize, Define, Ideate, Prototype, Test, Reflect.
2. **A 15-minute script** (`SCRIPT.md`), generated from the speaker notes in `src/slides.js` (`npm run script`). About 1,800 spoken words; planned 14:17 including time for live demos.
3. **Product images in the app** (`../src/assets/products/*.webp`): nine AI-generated studio-style images, one per catalog product.
4. **Two hosted sites** on GitHub Pages (branch `gh-pages`), published with `npm run publish` (see below).

## Run it

```
cd case-study
npm install
npm run dev          # http://localhost:5173 (or the next free port)
npm run build        # static site in dist/, relative paths
npm run publish      # build app + case study, push both to gh-pages
```

Keys while presenting: `→ Space` next beat, `←` back, `G` overview (click to jump), `P` presenter mode (notes, timer, pace), `F` fullscreen, click a diagram or flowchart to zoom. Clicking a chapter bar jumps to that chapter. Controls show for a few seconds on slide 1, then hide (hover the bottom-right corner to bring them back). `#/12` jumps to slide 12.

## How it is built

- `src/slides.js`: every slide (copy, layout, theme, speaker notes). `src/timing.js` derives planned seconds from the notes.
- `src/main.js`: the engine. Navigation is never blocked (a new key press finishes the running transition). Steps (`data-step`, `onStep`) reveal beats on a slide. Phones are the **real app** in an iframe (`public/app/`), scaled to fit, and the list beside the hub phone drives it (`liveGo`). Live screens drift down slowly after about 2.4 s and stop on any touch, wheel or key.
- `src/flow.js` + `src/flows.js`: the four flowcharts. dagre lays out the graph, we draw it as SVG with right-angle lines, diamonds for decisions, Yes/No labels. Steps, branches and loops come from the Figma flow diagrams; edit a step in `flows.js`.
- `public/figma/`: exported Figma diagrams, sketches and sticky notes. `scripts/crop.mjs` crops exported slides down to the artwork (mood board, business canvas).
- `public/app/`: a **build of the app**, regenerated by `npm run publish`, or by hand: `cd .. && npx vite build --base=./ --outDir case-study/public/app --emptyOutDir`. After any app change, rebuild it or the case study shows the old app.

## Decisions already made (do not relitigate)

- **Live one-section-at-a-time**, not free scroll. Visual style matches the app: paper, ink, navy, one amber; Outfit for words, DM Mono only for numbers.
- **No 3D background.** The floating tabs and the amber orb were built, used as story devices, then removed at the owner's request. The slide transitions are a plain colour wipe.
- **One design system, shown once** ("The design system"): 15 tokens, no "then and now", no mention of an earlier version.
- **Do not mention the company SOP anywhere** in slides, notes, script or README. The vocabulary (POV and 5 Ws, How might we, affinity diagram, NUF test, information architecture, as-is and to-be, mood board) is used plainly instead.
- **Titles are conversational**, not labels ("Buying one thing shouldn't take twenty tabs").
- **Flowcharts are drawn natively**, in the site's style, from the real flow content; sticky notes are native cards with the real note text.
- **Business model** slide uses the revised canvas (no sponsored listings), cropped to the grid.
- **Product images are AI-generated illustrations** (ChatGPT image tool), square 800 px WebP, shown whole (`object-fit: contain`), with no caption (the owner asked for it removed). Large hero is capped at 460 px wide; thumbnails fill their 64 px squares.

## Checks (headless Edge, no browser needed on screen)

```
node scripts/check.mjs <outDir> 1 5-9 [--wait=3500] [--press=ArrowRight]   # screenshots of chosen slides
node scripts/test-nav.mjs        # rapid navigation, steps, live app control, auto-hiding controls
node scripts/test-drift.mjs      # live phones drift; the hub opens on the right question
node scripts/contrast.mjs        # WCAG audit of every text element on every slide
```

The contrast audit's only remaining findings are the large amber full stops on light-background headlines (a decorative accent, same call as in the app).

## Known limits

- The in-app browser pane only animates while it is visible; use the headless checks above to verify.
- The hosted links go stale whenever the app or presentation changes. Run `npm run publish`.
- Compare and Decision phones have no product images because those screens use solid colour blocks by design. Adding thumbnails would need an app change.
- The flowcharts are small in the slide view because they are wide; click to zoom.
- The hub slide starts the phone scrolled to the question tabs, so the product image is above the fold. The cover phone shows it.

## How the product images were made (in case you need more)

Prompted in ChatGPT on the owner's Brave browser (via the Claude in Chrome extension): one prompt per product, "same style and same background", square, no text. ChatGPT's page recycled its image list, so one image was wrong (a Bose shot saved as AirPods Max) and had to be regenerated; always check a contact sheet. Downloads from Brave stalled after a burst, so images were moved through the clipboard and saved with PowerShell, then resized to 800 px WebP in headless Edge. They are mapped in `../src/photos.ts`.
